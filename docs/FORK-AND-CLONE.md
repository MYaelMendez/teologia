# Fork · Clone · Teach / Bifurcar · Clonar · Enseñar

**Clone to learn. Fork to make it your own.**

A clone is a local working copy. A GitHub fork is a separate repository under your account that can develop independently and contribute improvements upstream. You can also clone your fork.

## Fork: start your own teaching project

1. [Fork TEOLOGIA on GitHub](https://github.com/MYaelMendez/teologia/fork).
2. Give your fork a purpose: a family, classroom, congregation, or community. Respect the upstream name and trademarks; do not imply institutional endorsement.
3. Clone your fork: `git clone https://github.com/YOUR-USERNAME/teologia.git`.
4. Record your source editions, language, lesson objectives, and human review status. Keep the provenance of every adapted item.
5. Share your work. Open an upstream pull request when it can benefit others.

## Clone: study or contribute locally

```bash
git clone https://github.com/MYaelMendez/teologia.git
cd teologia
python3 scripts/validate.py
```

## Principles

- No person must use AI or pay for hosting to learn from this repository.
- A fork does not inherit approval or institutional authority from its parent.
- Cite sources and translations; confirm license compatibility before redistributing materials.
- Never include learner private data in public forks.
- Give back through lessons, accessibility fixes, language improvements, or bibliographic records.

**#OpenSourceSince1517** is a contemporary educational metaphor, not a claim that Git or software licensing existed in the Reformation.
